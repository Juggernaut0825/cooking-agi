# 技术世界树：结构与维护

这不是一串 AI 模型的年表。它要帮助读者看见计算背后的条件：电从哪里来，数据怎样移动，程序怎样落到硬件上，模型怎样学习，谁使用它、谁承担风险。树是入口，时间线是历史，具体联系另有证据；三者不能混为一张“进化图”。

## 先把三件事分开

1. **领域分类**回答“这是什么问题”。首页固定少量主枝，不为每个热门模型或公司再加一枝。
2. **年代顺序**回答“当时发生了什么”。同一时期可以有许多平行路线，先后出现不等于互相导致。
3. **跨领域联系**回答“具体借用了什么”。只有读过来源、能说清机制的联系才登记；未展开时不显示满屏交叉线。

大树的上下位置不是知识高低，也不是学习先修顺序。尤其不能把数学写成操作系统的后代，或把电网、Linux 的发展目的写成 AI。人与组织贯穿所有层，放在树冠只是入口位置。

## 四组主枝，十一条历史

| 全景分组 | 主枝 | 子方向的归属范围 |
|---|---|---|
| 物理基础 | 电力与机房 | 发电与电网、配电、UPS、冷却、数据中心容量和能耗 |
| 物理基础 | 芯片与计算 | 晶体管、CPU、GPU、专用加速器、制程、封装；NVIDIA / AMD 等并行路线 |
| 物理基础 | 内存与存储 | 寄存器、缓存、DRAM / HBM、持久化介质与存储层次 |
| 物理基础 | 网络与互连 | 互联网、集群网络、RDMA、PCIe、芯片与 GPU 互连 |
| 软件与系统 | 系统软件 | 操作系统、编译器、驱动、运行时、CUDA / ROCm、执行框架 |
| 软件与系统 | 分布式与服务 | 并行计算、数据库、云、调度、容错、训练与推理服务 |
| 方法与证据 | 数学与算法 | 可计算性、复杂度、数值计算、统计、优化、搜索与控制 |
| 方法与证据 | 数据与评估 | 数据获取、标注与反馈、基准、实验方法、治理与维护 |
| 方法与证据 | 模型与学习 | 符号与统计方法、神经网络、视觉、语音、语言、图学习、RL、因果方法 |
| 应用与人 | 应用与产品 | 科学计算、搜索与推荐、机器人、自动驾驶、医疗、创作和助手 |
| 应用与人 | 人、协作与责任 | 研究组织、资助、开源、标准、数据劳动、安全与无障碍使用 |

上表是收录范围，不是完成清单。每个主枝的 `next` 必须先承认已收录或在其他主枝提及的内容，再说明缺少哪些独立历史或部署案例。例如已有 Model 85 缓存、MI300 封装、Hopper 的 NVLink、MYCIN 和 Stable Diffusion，不能再笼统声称缓存、封装、互连、医疗或创作工具完全空白。当前 77 个代表节点用于组织阅读，远不是这些领域的完整历史。

## 读者怎么走

- **只想有个概念**：看世界树和每个年代的一段概括。
- **只关心一个方向**：点枝头的领域名（或表格视图里的领域），下面的年表只留这一条线，地址带 `?field=`。
- **想钻深一点**：卡片直接展示主体介绍，「背景与后续」「原始资料」按需展开。
- **想知道几条线怎么相遇**：悬停星点会点亮有记录的联系，卡片上也直接写着「用到 / 被用于」。

不开 JavaScript 时，树、表格和全部年表照常可读，只是没有悬停说明和筛选。

### 世界树怎么画（2026-10-12 重做）

借中国神话里的建木：《山海经·海内经》说它「百仞无枝，上有九欘，下有九枸」，《淮南子·墬形训》说它立在「天地之中」，「众帝所自上下」。页面引用这两句时要和原文一致，白话解释另写，不把神话说成史实。

- **同根**：每个领域是一根发光的纤维，全部从同一个根长出，在主干里互相编织；主干对应第一个年代（1882–1955），起源节点就在主干上。地下画九条根（下有九枸）。
- **分枝**：一个领域在它第一个收录节点所在的高度离开主干，长到最后一个节点为止。越早分出的枝排得越靠外，避免后来的枝横穿早期的枝。树冠高低不齐，正好说明哪条线收录得少。
- **时间**：越往上越晚；每个年代占一条横带，同一高度属于同一个年代。横带高度按该年代最拥挤的领域分配，不代表实际年数。
- **交织**：枝之间的细藤只来自数据里的 `connections`；主干内的编织是画法，不代表联系。
- **落地生根**：领域可以在数据里写 `root`（`from` 必须是本领域的节点，`label` / `note` 双语）。气根从这个节点垂回地面，表示这条线后来自成一片，并不是为 AI 而存在。目前给了网络（Web 之后）和系统软件（Linux 之后），可以改。
- **质感**：舞台固定为夜景（深色径向渐变、星尘、细颗粒），不随页面主题变色；节点是白色星核加领域色光晕，代表作带十字星芒；树冠顶上一团白光。配色用经过校验的四个类别色，按分组相邻排列；每个点都有文字，颜色只是辅助。
- **几何确定**：坐标和星尘都由数据和固定种子算出，同样的数据每次构建结果一样，新增节点不需要手填坐标。宽屏和窄屏各有一套布局，窄屏不放节点标签，靠表格视图补充。

表格视图（领域 × 年代）默认折叠，作为同一数据的文字版本；空格表示还没收录，不代表那时没有进展。

导航中它属于独立的 `history` 大类。用 `nav.toml` 的 `include` 调整归类，继续保留 `learn/technology-timeline.html` 和 `learn/rl-timeline.html` 的旧地址；新分组同时登记 `collaboration.toml`。

## 内容放在哪里

- `static/technology-tree-data.json`：领域、年代、小树、代表作品、已核对的联系、落地生根的设置和双语来源说明，当前为 version 3。
- `technology_chronicle.py`：验证数据并在构建时生成 HTML（世界树、表格视图、年代条和年表），正文和来源不依赖浏览器请求 JSON。
- `world_tree.py`：从同一份数据生成世界树 SVG（宽屏、窄屏两套），不复制节点正文。
- `static/chronicle.js`：悬停说明、联系高亮、领域筛选、年代高亮和旧分享链接（`?milestone=`、`?era=`、`?field=`）的兼容；不访问存储或外部服务。
- `static/chronicle.css`：编年史页面的全部样式，含窄屏、打印和减少动效。
- `static/technology-tree.css`：只剩其他笔记里 `.tech-timeline` 小时间线的样式。
- `../learn/technology-timeline.md` 与 `.en.md`：页面标题、简短引言和编年史挂载点。

旧版的可缩放画布、节点弹层和年代展览（`world_grove.py`、`world-grove.js`、`technology-atlas.js`、`world-exhibit.js`、`technology-tree.js`）已在这次重做中移除，历史在 git 记录里。

## 页面职责

编年史展示年代、各领域的重要变化、代表工作和有来源的历史联系。交互只服务于浏览这些内容，不把页面变成学习路线、面试准备或系统设计教程。

选材标准、审核方法、缺口和维护计划留在本文件、证据记录与数据的 `topics.next` 字段中，不在读者页面追加解释我们如何策划这个功能的长文。节点本身的日期口径、来源和技术限制照常保留；这类信息属于历史内容，不是编辑流程。

已移除旧版末尾的学习路线、选材论证和文档问答系统示例。完整 ML 系统与学习路线仍在各自页面维护。旧 `branch-*` 链接落到对应历史节点，`selection` 回到全景，`connections` 落到历史联系，不恢复已移除的文章。

## 先判断值不值得收录

历史节点要能解释当时的问题，或帮助理解后来为什么这样设计。新方法要有后续研究、独立使用或公开实现支撑；单篇论文自报的提升不足以成为主树节点。日期近不是加分项，也不是排除理由。

`historical` 表示历史事件或特定版本，**不是过时或已停用**。专利申请、Model 85、某代 GPU 和具体产品发布均可使用这个标签；设计原则沿用至今，不等于原器件仍在部署。`adopted` 表示可复用方法或软件有实际使用或实现依据，**不是普遍最优，也不是当前装机量或支持状态的调查**；不能只凭旧产品公告断言具体型号今天仍在使用。`evolving` 用于尚未形成稳定做法的开放问题，**不是给新论文预留的广告位**。三个值不是有高低的证据评分；同一技术可以既有历史意义，又有后续采用。GRPO 的原论文负责定年，后续报告和 TRL / verl 文档负责说明采用，不能把后来文档的功能倒填到 2024 年。

核对原文的问题、设置与限制，别从一个实验推成业界共识。节点短文先说解决什么，再说重要边界；不要每一条都套“颠覆—赋能—演进”的句式。专业名称保留，中文解释独立读得懂，英文另写成自然的句子。

## 数据约定

分类结构是 `layers → topics`；时间结构是 `eras → branches → works`。`works` 存作品 ID，正文只在 `nodes` 中存一份。每个节点有一个主 `topic`，跨领域关系用 `connections` 单独记录。

- 不按公司建一级分类。CUDA 属于软件，Volta / Ampere / Hopper 属于计算架构；AMD 的 GCN、RDNA、CDNA 也放在对应领域。公司路线可作为将来的筛选标签，不复制正文。
- 缩写不决定归属：AMD Graphics Core Next 与图卷积网络都叫 GCN，但不是同一技术。KV cache 是模型执行时保存的张量，不等于 CPU 硬件缓存；FlashAttention 涉及训练和推理，不能只因与 vLLM 同组就写成服务系统。DeepSeek-R1 的训练报告归入模型与学习，不把它当作另一个产品发布节点。
- `connections` 的 `from` / `to` 必须指向已存在节点，`type` 区分用到、改用和互补。`description` 说明具体联系，`source` 必须来自起点节点已列的来源；结构验证只检查引用完整性，仍需人读原文判断是否成立。
- 连线不是时间必然性。GPU 与数据集共同参与 AlexNet，并不等于没有这个具体 GPU 产品就不可能出现视觉深度学习。
- 分支增长优先补已有主枝的子方向。只有放在任何现有领域都会长期误导时才新增主枝，并重新检查桌面布局；新增作品不需要改坐标或渲染代码。

- 每个年代写一段简短概括，突出当时的变化，不给每一年硬造一个突破。年代可以不连续，空白不代表当时没有研究。
- `featured` 选 1–3 个代表作品或产品，只作跳转入口。它们的完整介绍仍在小树里，不复制两份正文。
- 小树按这一时期的方向分组，默认收起。例如 2016–2018 年的 GNN 分支可以收纳 GCN、GraphSAGE、GAT。分组不表示三者是严格继承关系。
- 每个作品只放在一个年代的一棵小树中。跨领域联系在说明里讲，不靠重复节点凑热闹。
- `kind` 区分 `research`、`system`、`product`、`open`。论文、AlphaGo 这样的系统、ChatGPT 这样的公开产品，不是同一种事件。

- `id` 是稳定的链接标识。标题可改，已经公开的 ID 尽量不改。
- `year` 必须对应节点实际描述的事件，而非网页更新时间或最后修订日期。论文优先用原始公开年份，并区分会议出版年；实验器件、专利申请、项目公告、产品上市也要写清各自口径。例如晶体管是 1947 年实验与 1948 年论文，DRAM 是 1967 年申请与 1968 年授权，CUDA 是 2006 年公布与 2007 年公开测试版公告。计划供货不能写成已经交付，AlphaFold 2 的 CASP14 结果也不能与 2021 年论文混为一次发布。
- 历史报告优先固定版本。当前 R1 节点及其引用使用 2025 年的 v1，不用 2026 年修订的 v2 充当当年的报告；Tülu 3 则说明 2024 年初稿与所引 2025 年修订本的区别。
- “得到关注”和“首次提出”分开写。2012 年的 AlexNet 不是 CNN 的起点，GCN 也不是最早的 GNN。不用主观感受编热度曲线。
- `reviewed` 是资料核对日期，不代表地图覆盖了此前所有工作。
- `title`、`body`、`limit` 必须同时有 `zh` 和 `en`。不把整段中文塞满括号和缩写。
- `body` 先解释这项工作解决什么问题；可选的双语 `detail` 补机制或小例子。例子服务于解释，不能冒充原论文实验。节点正文在服务端完整生成，弹层复用同一份内容，不开 JavaScript 也能读。
- 年代 `summary` 讲这一时期的变化，分支 `summary` 讲当时具体遇到的问题，不复制领域的通用介绍。中文按中文的语序写，英文独立组织句子；关键事实、例子、限制和来源保持一致。
- `sources` 使用原始论文、作者资料或官方实现的 HTTPS 链接；来源文字可以保留论文原名。
- 年代顺序、归属、双语、来源和唯一 ID 由构建器检查；新增作品不能只写进 `nodes` 而不安排阅读入口。无需手填坐标或修改渲染器。
- 主干与枝条只是阅读装饰，长度不按时间比例绘制，也不表示引用量或影响力。开放问题用虚线区分，正文不降低透明度。

锚点约定：`field-{领域ID}`、`era-{年代ID}`、`twig-{年代ID}-{小树ID}`、`event-{作品ID}`。原有 `event-grpo` 等链接保留，切换语言继续定位同一作品或筛选分支。若跨链接的目标被当前筛选隐藏，恢复全部分支后打开目标，不能留下看不见的选中状态。

新增节点同时检查两种语言。不要自动抓取最新 arXiv 条目上树，也不要根据公司宣传给方法标“成熟”。

本轮逐项筛查 66 个节点、11 条覆盖说明、年代分组和 4 条显式联系，重点核对硬件、基础设施、事件与出版年份，以及跨领域概念混淆；未增加节点或修改稳定 ID。已修正具体硬件事件的状态、R1 的领域与版本证据、Linux 0.01 的许可边界、MYCIN 的报告年份和 FlashAttention 的训练语境，并用 1956 年 Logic Theory Machine 报告替代泛化的符号 AI 方向标记。图灵节点保留 1936 年收稿与宣读的时间，同时明确期刊出版记录为 1937 年。

逐项筛查不等于逐条外链全文复核：部分旧站点或 PDF 本轮不可读取，部分材料仅核对了摘要、日期或相关段落；采用状态也不是截至审查日的部署普查。原始论文的自报结果、厂商发布日期、计划供货与后续实际部署仍须分别判断。完整的本轮处置清单与未核实边界写入本地审查记录，不把结构测试通过称为全部史实验收。
