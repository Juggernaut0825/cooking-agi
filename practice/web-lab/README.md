# 用这个网站，学着做一个小项目

**中文** · [English](README.en.md)

> 原创教学项目 · Python 3.12 · 最近核对：2026-10。静态站用本站作例子；阅读清单是独立的本地练习，不会收集本站读者的数据。

会写几个函数以后，常常还是不知道怎么把东西交给别人用。代码放在哪里？页面为什么能打开？改了一行，怎么知道没把别处弄坏？

不用先造一个很大的应用。我们就拿你正在看的站点开头，再做一个小小的阅读清单。比如把“BERT”加入待读，读完后改成“已读”，关掉程序再打开，记录还在。这个需求不复杂，但前端、API、数据库和测试都会经过一遍。

## 先分清：这两个项目不是同一种网站 {#two-projects}

| | 本站 | 阅读清单练习 |
| --- | --- | --- |
| 页面从哪来 | Markdown 在构建时变成 HTML | 浏览器加载页面，再向 API 取记录 |
| 交互发生在哪里 | JavaScript 在浏览器运行 | 浏览器发请求，Python 处理，SQLite 保存 |
| 数据放哪里 | 文章在仓库；收藏等阅读记录在浏览器本地 | 清单保存在运行服务的电脑上 |
| 发布方式 | 构建产物交给 GitHub Pages | 本例只在本机运行，公开部署还需要补安全与运维 |
| 练到什么 | 构建、自动检查、发布与回退 | 请求、校验、持久化和错误处理 |

**有按钮、有动画，不代表有自己的后端。** 本站是静态站；阅读清单才是这条路线里的 full-stack（全栈）练习。这里的“全栈”指你能走通几层，不是已经做了一个可供多人使用的生产服务。

## 想动手，按这个顺序 {#route}

- [本站怎样构建和发布](static-and-ci.md)：可以直接在自己的 fork 上练 CI/CD，不改本站部署设置。
- [做一个阅读清单](reading-list.md)：附完整本地代码和测试；从一条 POST 请求开始讲。
- [评估报告与 CI](eval-report.md)：把六道题的新旧结果做成网页，看看总分上涨时，为什么仍有理由拦下发布。
- [接下来做什么](next-projects.md)：再给搜索、分页、后台任务各留一个可完成的小目标，不只是列项目名。

只想先懂原理，读每篇开头的例子和流程即可。想写代码，再往下看运行步骤、测试和取舍。

## 跑完以后，应该能说清什么？ {#finish}

不看代码，试着解释：“我点击保存，数据经过了哪里？什么时候才算成功？如果页面显示失败，但数据库已经写入，重试会怎样？”能把这些问题说清楚，比一次装上很多框架更有用。

这里不会承诺练完就掌握 full-stack，也不是 SDE 面试大全。它补的是 ML 项目经常需要、却容易被跳过的一段：把一个功能做出来，确认它工作，再交给别人使用。
