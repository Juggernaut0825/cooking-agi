# 按计划学习

**中文** · [English](study-plan.en.md)

想系统学一遍，可以先用一个小练习判断从哪里开始，再把阅读和动手安排在一起。这页介绍怎么选内容、安排时间，以及保存记录，方便下次接着学。

[面试准备入口](README.md#plan) · [快速复习](speedrun.md)

## 先确定从哪里开始 {#build}

如果 ML 接触不多，从 [起步路线的一次预测](speedrun-start.md#prediction) 开始。算完后问自己：输入是什么，模型给出什么，loss 又比较了什么？

- 看不懂列表和函数：先做 [Python 小例子](speedrun-start.md#first-two)，再回来。
- 会写代码，但没学过训练：跳过语法，从预测与 loss 接到 [一次参数更新](speedrun-start.md#update)。
- 这些都很熟：直接做下面的[自查练习](#refresh)。

按主题选起点就好。比如做过系统开发、但没接触过模型训练，可以跳过 Python，从预测和 loss 开始。

## 已有基础，用练习查漏补缺 {#refresh}

挑一个和目标岗位有关的小任务，先不查答案。做不出来时，分清是原理没懂、代码写不出，还是不会检查结果，再回看对应章节。

| 试一下 | 哪里卡住，就从哪里补 |
| --- | --- |
| 写出一个 batch 的平均 loss，换一种分批方式再算 | [聚合与分母](code-comprehension.md#aggregation)：你到底在平均什么 |
| 写一个 causal attention，标出各步 shape | [ML Coding](../learn/ml-exercises/README.md)：shape、mask 和测试 |
| 用一个小图说明 DFS 和 BFS 的访问顺序 | [遍历方法](algorithms/traversal.md)：栈、队列和 visited |
| 画出一条 LLM 请求从入队到返回 token 的路径 | [推理框架拆解](../06-systems/inference-frameworks.md)：调度、缓存与执行 |
| 讲一个项目，说明为什么没选另一个方案 | [项目准备](../career/prepare.md)：约束、个人贡献和证据 |

能独立完成的部分可以跳过。只记得结论时，就用一个具体输入验证它，看看自己能否解释中间每一步。

## 每次安排一个练习 {#sessions}

可以先留 **30–60 分钟有效学习时间**，用于阅读、写代码或复习，休息不计入。这个时长是一次安排的参考，不代表一个单元一定能在一小时内学完。

在[学习台](dashboard.md#schedule)里选有空的日期，每次时长可以不同，比如周二 25 分钟、周六 70 分钟。学完后可记录实际日期和时长，也能改期、补记、撤销完成或恢复已移除的安排。这里没有连续打卡要求，完成一次练习也不会自动把笔记标为已掌握。

| 顺序 | 先读一点 | 这次动手做什么 | 留下什么，方便下次继续 |
| --- | --- | --- | --- |
| 1 · 输入与预测 | [一次预测](speedrun-start.md#prediction) | 手算两个样本的预测和 loss，再用 Python 核对 | 一个可运行的函数，写明输入和预期输出 |
| 2 · 更新参数 | [一次更新](speedrun-start.md#update) | 改一次学习率，观察 loss；解释步子太大时发生什么 | 参数更新前后的数值和一个疑问 |
| 3 · 写成训练循环 | [张量与 PyTorch](../00-foundations/pytorch/README.md) → [训练循环](../00-foundations/pytorch/training-loop.md) | 用一个小 batch 跑前向、反向和更新；区分 train / eval | 一个能重复跑的脚本和一次检查结果 |
| 4 · 练一个算法方法 | [Hash Map](algorithms/hash-and-prefix.md) 或 [DFS / BFS](algorithms/traversal.md) | 自己写一次，补重复值或成环的例子，解释复杂度 | 一个边界测试，以及方法适用的条件 |
| 5 · 接到目标方向 | [按岗位选练习](ai-roles-prep.md) | 从下面选一条分支，只做其中一个练习 | 一个实现、实验记录或设计草图 |
| 6 · 合起来讲一次 | [代码理解](code-comprehension.md) 与 [项目准备](../career/prepare.md) | 给代码改一个要求；用一个项目解释自己做过的选择 | 这次没讲清的两处，下次从其中一处继续 |

1–3 适合刚接触 ML 的读者；算法也可以单独并行练，不必等模型部分全部学完。每个单元都可以拆开，或者在已经会做时跳过。

## 按岗位继续准备 {#roles}

### MLE / Research Engineer

从 [ML 手写练习](../learn/ml-exercises/README.md) 里选一个实现，例如稳定的 softmax 或 attention。先做小输入，再检查输出、梯度和边界。之后挑一个和岗位相关的训练或评估问题，不必把每个模型家族都读完。

如果做 LLM，接着看 [后训练实践](../practice/post-training/README.md)；如果做推荐与检索，选 [推荐系统拆解](../practice/recommender-systems/README.md)。方向不同，后续准备也不该一样。

### Inference / ML Systems

沿 [一条推理请求](../06-systems/inference-frameworks.md) 看每个模块的输入和输出，再挑一个约束：显存不够、排队太久，或者长请求拖慢短请求。写下两种方案，说明各自改变哪一段、还需要测什么。

接到 [系统设计练习](../learn/system-design/README.md) 时，先定 workload 与延迟目标，再谈组件。算法和读代码仍要留时间，不能只练架构图。

### 通用 Coding / SWE

先把 [Python 与 LeetCode](leetcode.md) 和 [读代码](code-comprehension.md) 放进自己的安排。每次练一个方法，再改一个条件看看还能不能用。ML 部分不是通用 SWE 的必修课。

本站主要从 ML 与 AI 系统的角度组织内容，不是覆盖所有 SWE 岗位的准备手册。具体需要补哪些语言、后端或系统知识，要看岗位和面试说明。

### Research Scientist

挑一篇自己做过或认真读过的论文，讲清问题、对照实验和结论的范围，再提出一个能区分两种解释的后续实验。[评估基础](../07-evaluation/README.md) 可以帮你检查“指标涨了”是否支持自己的解释。

同时练相关实现，不把理论讨论和工程能力完全分开。研究方向的专业要求差别很大，这条路线不替代你所在领域的积累。

## 留下记录，下次继续 {#resume}

结束前留三行就够了：**这次做了什么、哪里还不清楚、下次先试什么**。比如：

> causal mask 能跑了，但还没测 padding。下次构造两条长度不同的序列，先手写预期 mask。

文章上方的「学习记录」可以选状态、写备注，输入后自动保存在当前浏览器，中英文共用。下次打开[学习台的「笔记与备份」](dashboard.md#progress)，就能找到这些记录。要给文章排时间，点「安排这篇笔记」即可；也可以继续用自己的代码和笔记记录进度。

隔了一段时间再回来，先跑一下上次的例子。还能解释清楚，就往下做；忘了哪一步，再回头补。

## 备份与恢复 {#backups}

换电脑、换浏览器，或清理网站数据前，先导出一份备份：

1. 在[「笔记与备份」](dashboard.md#progress)点「导出进度」，下载 JSON 文件。学习记录、安排与完成记录、收藏、最近阅读、阅读位置和更新设置都包含在内。
2. 在另一台设备打开学习台，把文件拖入备份区，先查看预览。
3. 确认保留哪些记录，再导入。默认保留当前记录、补上缺项；也可以选择时间较新的一份，或采用备份里的记录。旧备份缺少的数据类型不会清空现有记录。

- **网站更新不重置进度。** 记录保存在浏览器里，不在源码中，不需要 fork 或 clone。正常更新网页、`git pull` 都不会覆盖记录；但域名、协议或本地端口变了，需要导入备份。
- **浏览器数据也可能丢。** 清理网站数据、关闭无痕窗口，或浏览器自动清理存储，都可能删除记录。备份文件请另存一份，不要只依赖浏览器。
- **导入不会上传文件。** 处理在本地完成。JSON 没有加密，含私人备注，别放进公开仓库。未保存的表单和主题等显示偏好不在备份里；「最近阅读」只记录本站页面，不读取 Chrome 浏览历史。
- **章节改名不影响记录。** 进度按固定 ID 匹配，不按标题、顺序或语言匹配；维护者改名时需要保留这个 ID。暂时找不到的章节仍会保留记录。遇到不支持的备份版本，页面会提示，不会覆盖现有数据。

浏览器里另有**最多三份恢复副本**，可先预览再恢复，但不是每次输入的完整历史。清理浏览器时，这些副本也可能一起被删。你可以把导出的文件放到自己的 iCloud / Drive 同步文件夹；本站不连接云盘，也不自动同步设备。两台设备都改过同一条记录时，需要在导入预览里选择保留哪份。

在[「更新与设置」](dashboard.md#updates)关注主题后，新文章默认加入「待安排」，**不会自动排进日历**；自动加入也可以关闭。已有学习记录的文章如果补充了实质内容或有纠错，会显示提醒；只改标题或排版不会提醒。「标记更新已读」只处理这条提醒，不会更改学习状态。
